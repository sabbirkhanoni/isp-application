# Phase 5 — MikroTik: suspend and reconnect

## What the owner gets

- **Routers** page (admin): add routers (direct or agent), test the connection, see last contact, deactivate.
- **Customer page**: assign a router, **Suspend** (unpaid bill / other reason) and **Activate**.
- Internet is switched on/off on the router automatically within about a minute:
  - customer becomes ACTIVE (new customer "activate now", first payment, manual activate) → PPPoE user enabled
  - customer suspended → PPPoE user disabled and the live session dropped
- **Auto-reconnect:** a customer suspended for _unpaid bill_ is reconnected as soon as nothing is past its due date (paying only part keeps them suspended). A _manual/other_ suspension is never lifted by a payment.
- **Auto-suspend (off by default):** `AUTO_SUSPEND=true` suspends customers whose bill is more than `AUTO_SUSPEND_GRACE_DAYS` (3) past due. Audited as an automatic action.
- Failed router jobs appear with the reason and a **Retry** button.

## Settings (Render environment)

| Name                                      | Meaning                                                                                  |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| `ROUTER_SECRET`                           | Encrypts router passwords. Generated by render.yaml. Do not change after saving routers. |
| `ROUTER_DRY_RUN`                          | `true` = only log, touch no router (render.yaml starts with true).                       |
| `AUTO_SUSPEND`, `AUTO_SUSPEND_GRACE_DAYS` | Automatic suspension, default off / 3 days.                                              |

## Go-live checklist (first real router)

1. Router: enable `www-ssl` (or `www` on a trusted LAN) and create a user with `rest-api,write,policy` rights. Or use the agent (agent/README.md).
2. Admin → Routers → Add → **Test connection**.
3. Keep `ROUTER_DRY_RUN=true` and suspend/activate **one test customer** whose PPPoE user exists; check the log shows the intended change.
4. Set `ROUTER_DRY_RUN=false`, repeat with the test customer and confirm on the router that `ppp secret` flips `disabled` and the session drops.
5. If a path or field differs on your RouterOS version, only `routeros-rest-gateway.ts` (and the same three calls in `agent/router-agent.mjs`) need a change.

## Not in this phase

Creating PPPoE secrets/profiles from the system, speed-profile changes, DHCP/static/hotspot enforcement, and SMS on suspension.

## API

`GET/POST /routers`, `PATCH /routers/:id`, `POST /routers/:id/test`, `POST /routers/:id/token`, `GET /network-jobs?status=`, `POST /network-jobs/:id/retry`, `POST /customers/:id/suspend|activate`, and for the agent `POST /agent/claim`, `POST /agent/jobs/:id/result` (bearer token).

## Verified

112 API tests (21 new for routers, jobs, retries, agent, auto-reconnect, grace period) + 4 driver tests against a mock RouterOS; web tests, lint, typecheck, build; browser run (add router, test connection, create customer on router, suspend → real REST calls made, token shown once); agent script run against the mock.
